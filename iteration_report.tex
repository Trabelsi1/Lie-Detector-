\section{Overview}

This iteration focused on completing the backend service layer and REST API for the Lie Detector Arena game. The objective was to ensure all gameplay entities have corresponding service classes and REST endpoints, making the backend fully functional for frontend integration.

\section{Implemented Components}

\subsection{Repository Interfaces}

The following repository interfaces were added to support persistence layer queries:

\begin{itemize}
    \item \texttt{ChatMessageRepository}: manages chat messages by round
    \item \texttt{GameRepository}: retrieves games by room
    \item \texttt{InvitationRepository}: finds invitations by room or receiver
    \item \texttt{PlayerProfileRepository}: retrieves profiles by player
    \item \texttt{ScoreEntryRepository}: finds scores by game or player
\end{itemize}

\subsection{Service Classes}

Nine service classes were created to handle business logic for the game domain:

\begin{itemize}
    \item \texttt{PlayerService}: manages player creation and retrieval
    \item \texttt{PlayerProfileService}: handles player statistics and profiles
    \item \texttt{GameService}: orchestrates game creation and retrieval
    \item \texttt{RoundService}: manages round progression and queries
    \item \texttt{StatementService}: handles statement submission and retrieval
    \item \texttt{VoteService}: processes votes with conflict detection
    \item \texttt{ChatMessageService}: manages chat communication
    \item \texttt{InvitationService}: handles invitation workflow
    \item \texttt{ScoreEntryService}: tracks player scores
\end{itemize}

\subsection{REST Controllers}

Nine REST controllers were implemented to expose the service layer as HTTP endpoints:

\begin{itemize}
    \item \texttt{PlayerController}: \texttt{/api/players}
    \item \texttt{PlayerProfileController}: \texttt{/api/profiles}
    \item \texttt{GameController}: \texttt{/api/games}
    \item \texttt{RoundController}: \texttt{/api/rounds}
    \item \texttt{StatementController}: \texttt{/api/statements}
    \item \texttt{VoteController}: \texttt{/api/votes}
    \item \texttt{ChatMessageController}: \texttt{/api/messages}
    \item \texttt{InvitationController}: \texttt{/api/invitations}
    \item \texttt{ScoreEntryController}: \texttt{/api/scores}
\end{itemize}

Each controller follows REST conventions: \texttt{POST} for creation, \texttt{GET} for retrieval, with support for filtering by related entities.

\subsection{Backend Tests}

A comprehensive test suite was added:

\begin{itemize}
    \item \texttt{UserServiceTest}: unit tests for user creation and retrieval
    \item \texttt{GameRoomServiceTest}: unit tests for room operations and player linking
    \item \texttt{BackendControllersTest}: integration tests for all REST endpoints using WebMvcTest
\end{itemize}

All tests use Mockito for service mocking and Spring MockMvc for HTTP testing. The test suite passes with 16 successful tests and 0 failures.
